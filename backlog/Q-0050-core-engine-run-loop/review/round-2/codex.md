## Findings

- **blocker** — `packages/core/src/engine/engine.ts:252`: Producer execution runs independently of event consumption, so it can persist `completed` before the consumer abandons the stream. For example, an empty flow queues its banner and completes `finishRun()` before the first `next()` returns; breaking after that banner calls `finaliseAbandonment()`, but aborting at line 257 cannot replace the already-written completed outcome with `interrupted`. This violates AC-5’s central safety guarantee that consumer abandonment stops unobserved work and persists an interrupted terminal record with counters spent. Couple execution or terminal commitment to delivery state so abandonment can win until the consumer has consumed the terminal event, and add the required composed `runFlow` test that breaks after an early event and asserts an interrupted record rather than completed.

- **major** — `packages/core/src/engine/channel.ts:100`: `abandon()` awaits finalisation but does not latch the iterator as terminated, clear buffered delivery, or prevent `next()` from starting/continuing the producer. After `return()` resolves, another `next()` can still dequeue events; worse, calling `return()` before the first pull and then `next()` starts a run that the caller already abandoned. This contradicts the solution contract that `return()` “closes delivery” and can allow work to resume after cancellation. Record an abandoned/terminated state that makes every subsequent pull return `done: true`, prevents lazy start, and prevents further queued delivery.

- **nit** — `packages/core/src/engine/routing.ts:84`: `runStep` allocates `gateId` before `askGate` evaluates its automatic and dry-run short-circuits. Consequently, a gate that is never asked consumes an ID, as the test explicitly expects, despite the solution requiring automatic and dry short-circuits to run before a question is allocated. Allocate the ID only on the branch that emits a gate question, and update the correlation test to expect IDs only for questions actually presented.
