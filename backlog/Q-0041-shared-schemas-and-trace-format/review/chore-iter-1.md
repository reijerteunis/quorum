# Review — Q-0041, chore iteration 1

major: packages/shared/src/flow.ts:207 The ordered `z.union` does not commit to the step kind selected by the engine’s presence-based dispatch. If a discriminator-specific schema fails, a value such as `{id: 'x', gate: 42}`, `{id: 's', type: 'script', run: 5}`, or `{id: 'f', fan_out: 42}` falls through to the permissive `agentStepSchema`, whose `.passthrough()` accepts the discriminator fields as unknown keys. The parsed type therefore classifies engine-dispatched gate/script/fan-out steps as agent steps and fails to validate their structure. Implement presence-aware preprocessing or a custom/refined union that selects exactly one branch using the engine’s precedence and validates that selected branch without fallback.

major: packages/shared/src/flow.ts:221 `consumes` and `produces` use the ten-member `stageSchema`, although `lintFlow` only checks that these fields are truthy. Consequently `{name: 'x', consumes: 'custom', produces: 'custom-next', steps: []}` succeeds in `lintFlow` but fails this schema, violating AC-3’s binding “lint succeeding implies schema parsing succeeding” property and adding a semantic rule the port did not previously enforce. Keep these flow fields structurally typed as strings so lint behavior is preserved, or add the stage-membership rule to lint only in an explicitly authorized behavior-change ticket.
