# Q-0039 code review — run 2, iteration 3

major: packages/core/src/run-history/writer.ts:333 `fs.mkdirSync(path.dirname(file), { recursive: true })` executes outside the claim’s error translation, so an unusable lock root (for example, `.quorum/locks` is a file or cannot be created) throws a raw filesystem error instead of the explicit `FlowError` refusal AC-7 requires. The CLI only renders `FlowError` and `IntegrationError` through its normal one-line exit-1 path, so this new failure mode can leak an unhandled error despite `acquireRunLock`’s own contract promising `FlowError` when the lock cannot be created. Catch lock-root creation failures, translate them into the same condition-only `FlowError` shape as `openSync` failures, and add a focused test for an uncreatable lock directory.
